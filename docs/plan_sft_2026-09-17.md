## 1. Chẩn đoán bằng số (đo trong repo, không phải phỏng đoán)

### 1.1 Ngân sách token pretrain
| | Số thật |
|---|---|
| Token/step | `batch 8 × grad-accum 2 × block 256` = **4.096** |
| Đã train | 46.000 step = **~188M token** |
| Corpus | 4,95B ký tự ≈ **1,15B token** |
| Một vòng | **~23 đêm** Kaggle (12k step/đêm = 49M token) |
| Hiện tại | **~16% một vòng** |
| Token/param | **1,27** (Chinchilla ~20) |

→ Mỗi đêm Kaggle = +26% token ≈ **−2…3% loss**. Thật, nhưng nhỏ, và không đổi *chất* trí tuệ.

### 1.2 Bằng chứng: model "biết" nhưng không "nói ra"
`bench.py` có hai thước: `pass_rate` (tự sinh) và `lp_pass_rate` (chấm điểm đáp án đúng).

| Lĩnh vực | pass_rate | lp_pass_rate | Đọc ra |
|---|---|---|---|
| factual | 0,045 | **0,727** | biết, không nói ra |
| safety | 0,000 | **0,833** | biết, không nói ra |
| vietnamese | 0,000 | **0,591** | biết một nửa |
| instruction_following | 0,150 | 0,300 | yếu |
| code | 0,222 | 0,222 | yếu |
| math | 0,125 | 0,125 | yếu |
| long_context | 0,000 | 0,524 | yếu thật |

**Kết luận quan trọng nhất:** thêm step pretrain *không sửa được* khoảng cách này. Nó là vấn đề **dữ liệu SFT + định dạng**, không phải số bước.

### 1.3 Nguyên nhân gốc của echo: corpus SFT chỉ có 755 câu trả lời


## 3. Thiết kế corpus SFT mới (việc tối nay)

Nguồn: `data/seed/hf/*.jsonl` + `data/seed/*.jsonl` + synth từ `data/raw` (76 file) + literary echo nhỏ.

| Thành phần | Cách lấy | Vì sao |
|---|---|---|
| HF instruction | `--hf-max-per-dataset 20000` (reservoir sampling) | 8 nguồn × 20k = **160k hội thoại**, cân bằng: ~12,5% tiếng Việt, ~12,5% toán, ~12,5% code |
| Seed tay viết | 365 conv, `--seed-duplication 1` | bỏ hẳn cơ chế nhân 40 gây echo |
| Synth Q&A | `--synth-samples 800` | giữ mẫu "giải thích/định nghĩa" nhưng không lấn át |
| Literary echo | `--literary-target-mb 0.5` (thay 2.0) | giữ chút văn xuôi, tránh loãng chat data |
| Dedup | **mới**: `--max-identical-answers 4` | xoá hội thoại trùng + chặn 1 câu trả lời lặp vô hạn |
| Chống nhiễm benchmark | giữ nguyên (mặc định ON) | doc trùng n-gram với `data/eval/probes.jsonl` bị xoá |

**Ngân sách token:** corpus mới 36,9M token (cũ 3,4M). SFT 4.000 step × 2.048 = 8,2M token → **0,22 epoch** thay vì 2,4 epoch (2,4 epoch chính là học thuộc). Muốn ~1 epoch cần ~18.000 step (~10h local) — để dành khi A/B đã chứng minh data mới thắng.

### 3.1 Kết quả build thực tế (đêm 16/09, đã chạy xong)

| | CŨ (08/05) | MỚI (16/09) |
|---|---|---|
| Dung lượng | 14,8M ký tự (~3,4M token) | **158,7M ký tự (~36,9M token)** ×10,9 |
| Lượt assistant | 30.020 | **157.143** |
| Câu trả lời **duy nhất** | **755** | **152.303** ×202 |
| repeat ratio (echo risk) | **0,975** | **0,031** |
| Ký tự tiếng Việt | 0,16% | **1,31%** ×8 |
| Câu lặp nhiều nhất | `"2 + 2 = 4."` ×120 | `"你好"` ×30 |
| Nguồn | 365 seed ×40 + synth | 142.484 hội thoại HF + 746 seed + 145 synth + 355 literary |

Log build: `[HF ]` 8 nguồn × 20k (openhermes, bactrian-vi, metamath, alpaca, oasst2, code-alpaca, dolly 15k, gsm8k 7,5k) → `[Dedup]` bỏ 267 hội thoại trùng + 722 hội thoại lặp đáp án → `[Output]` 142.741 document / 151,35 MB → contamination check **xoá 36 doc** dính n-gram của `data/eval/probes.jsonl`.

**Đổi trong code (đã làm):**
1. `dedup_conversations()` + `answer_stats()` — hết 755-câu.
2. `--max-identical-answers N` / `--no-dedup`; `--seed-duplication` mặc định *auto* (1 khi có HF, 40 khi chỉ có seed tay).
3. **Reservoir sampling** trong `_load_jsonl_conversations(max_conversations=…)`: openhermes 1M dòng/1,6GB trước đây nạp trọn vào RAM (máy chỉ 16GB) — giờ bộ nhớ có chặn.
4. 8 test mới: `tests/test_corpus_dedup.py`.

**Rollback:** corpus cũ đã sao lưu → `data/chat_train_pre_hf_2026-09-16.txt` (15MB). Dựng lại bằng:
`python build_instruct_dataset.py --seed-duplication 40 --no-hf-seed`.

## 6. Rủi ro & guardrails

| Rủi ro | Chặn |
|---|---|
| SFT trên HF data làm mất văn phong pretrain | giữ literary echo 0,5MB + tiếp tục pretrain hàng đêm (phân bổ 90/10) |
| Nhiễm benchmark → điểm ảo | contamination check ON + `data/eval/probes.jsonl` **không bao giờ** được train |
| Học thuộc corpus mới | ≤ 1 epoch; theo dõi `repeat_ratio` sau dedup |
| Tràn RAM khi build | reservoir sampling (đã thêm) |
| Mất bản chat đang tốt | golden `jingpt_chat_46k_sft4k.pt` vẫn còn; picker Model Lab đổi A/B được |
| Nhầm data cũ | `data/chat_train_pre_hf_2026-09-16.txt` giữ nguyên |

## 7. Những thứ **không** làm trong đợt này (chống loãng)

- **Không** tăng param lên `medium` 360M: 1,27 token/param nghĩa là tham số đang *đói dữ liệu*; to hơn = loãng hơn, chưa kể vỡ checkpoint 46k.
- **Không** đổi tokenizer: BPE 16k đã ổn với tiếng Việt (1,06×).
- **Không** RLAIF/preference tuning trước khi SFT sạch (ưu tiên 1 trước, `train_pref.py` để đợt sau).
- **Không** tăng TinyStories; đổi mix pretrain để dành cho lần build corpus kế tiếp (đêm khác), vì build lại 5GB tốn vài giờ CPU.
